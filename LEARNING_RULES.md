# Learning Rules

## Core principles

1. One repository, one learning journey.
2. No disconnected mini-projects.
3. Build skills around a single evolving master application.
4. Keep personal understanding, mistakes, and debugging notes.
5. Prefer depth over volume.
6. Advance only after proof of understanding.

## Completion standard

A concept is complete only after:

- Theory understood
- Manual implementation
- Practice completed
- Project application
- Testing and debugging
- Explanation without notes
- Assessment passed

## Levels

- Basic: I understand it.
- Intermediate: I can use it.
- Professional: I can design with it.

## Daily workflow

Every concept should eventually include:

- notes
- practice
- code
- diagrams
- assessment

For now, this repository contains the foundational structure and placeholder documentation only.
